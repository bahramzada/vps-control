# About vps-control

## Goal

`vps-control` is a local-first native macOS application for understanding and operating a VPS without routinely composing SSH commands. It provides a live visual dashboard and an interactive multi-tab terminal for exceptional work, including deliberate `sudo` elevation.

## Development status

Development is intentionally paused at the verified local MVP. The current application is designed and tested around one configured Ubuntu Server 24.04 LTS VPS. Compatibility detection, multiple server profiles, AZ/EN/TR localization, and AI Chat are documented future phases and must not be presented as current functionality.

## Repository

- GitHub: `https://github.com/bahramzada/vps-control`
- Visibility: private.
- Default branch: `main`.

## Verified environment

- Local environment: macOS 14 or later.
- Remote operating system: Ubuntu Server 24.04 LTS.
- Remote login user: `jarvis` with interactive sudo capability.
- Root SSH login: disabled.
- Password-based SSH login: disabled.
- Public management entry point: SSH only.
- Docker Engine and Docker Compose plugin: installed and previously verified with `hello-world`.
- Portainer: not installed; it remains a separately approved VPS change.

## Architecture

- Native SwiftUI application with targeted AppKit integration; no HTTP server or local TCP listener is used.
- The system `/usr/bin/ssh` client provides authentication, strict host-key verification, connection multiplexing, and PTY transport.
- Fixed versioned `VPSC/1` metrics, `VPSD/1` diagnostics, and NUL-delimited `VPSF/1` file-listing collectors run through SSH and install nothing on the VPS.
- CPU and network deltas are calculated locally. Visible refresh is 15 seconds and background refresh is 60 seconds.
- Slower diagnostics are isolated from live metrics and refresh at most every 5 minutes while active or 30 minutes in the background. Package status reads Ubuntu's existing update-notifier cache and never runs `apt update` on cadence.
- The file browser is lazy/manual, capped at 500 entries per directory, and never requests elevated permissions.
- Normal connections run as `jarvis`. The terminal exposes `sudo -i` only through an explicit high-risk UI state.
- SwiftTerm 1.15.0 provides the AppKit terminal emulator surface.
- The selected dark server-and-terminal artwork is compiled as the native macOS `AppIcon` asset catalog.
- Server configuration is stored in macOS `UserDefaults` or supplied through `VPS_CONTROL_*` environment variables. The private-key contents never enter the app or repository.

## Current product surfaces

- **Overview:** live OS, connection, CPU, RAM, disk, swap, uptime, load, UFW, Fail2ban, SSH-key, Docker, and redacted activity state.
- **Services:** read-only status for monitored systemd services, failed units, bounded listening-socket details, and terminal handoff for logs.
- **Docker:** daemon/version/socket status. Container management remains locked until a reviewed root-equivalent channel is approved.
- **Terminal:** up to six SSH PTY tabs, resize/reconnect/disconnect, explicit sudo mode, paste warnings, and session cleanup.
- **Activity:** local redacted events generated by the app; terminal contents are excluded.
- **Settings:** host, user, port, key path, known-hosts path, and SSH multiplexing preferences.
- **Files:** live read-only remote browser for `jarvis`-accessible directories with safe path encoding, metadata, parent/back/forward navigation, and bounded results.

- Package debug app: `Scripts/package-app.sh debug`.
- Package release app and verified ZIP: `Scripts/package-app.sh release`.

## Known limitations

- Portainer, native container actions, and Docker socket access are not enabled without separate user approval.
- File editing/upload/download and controlled privileged administration actions are future phases.
- Compatibility is currently verified only against Ubuntu Server 24.04 LTS; changing Settings credentials does not guarantee support for every Ubuntu release or server configuration.
- Persistence and UI currently manage one active server configuration even though the configuration model has a stable identifier.
- User-facing copy is primarily Azerbaijani; English and Turkish localization is not implemented.
- AI Chat, external model providers, Keychain-backed API credentials, and AI-proposed actions are not implemented.
- The app is ad-hoc signed for local use; Developer ID signing, notarization, and an updater are not configured.
- No open-source license has been selected yet.

## Non-goals

- Exposing a public web administration panel.
- Enabling root or password-based SSH login.
- Storing SSH private keys or sudo passwords.
- Performing silent or unconfirmed destructive VPS operations.
